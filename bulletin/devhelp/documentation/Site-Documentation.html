Content Block

Content in the main section of the site can be split into divs with the class content-block. This will provide padding to the content and also allow a background color to be added for color blocked sections of the site. (See Content Block Colors section of additonal information). For most pages, there only one content-block div needs to be used - you only need to use multiple on a page if you're adding different background colors to each.

Grid Container and Cells

The site uses a 12-column CSS Grid for the majority of layout and formating. The structure of the grid uses a "wrapper" div with the class grid-container which sets up the grid, places a max-width limit [1] on the site content. The first div under the header, nav, and footer sections should be a grid-container div.

The child divs of the grid-container div should have the class cell. You can nest grid-container divs within cell divs to achieve more complex layouts.

The overall structure looks like this for the main section of the site, with the content-block being replaced by header, nav, and footer as appropriate: 

          <div class="content-block">
            <div class="grid-container">
              <div class="cell"> Cell Content </div>
              <div class="cell">
                <div class="grid-container">
                  <div class="cell"> Cell Content </div>
                  <div class="cell"> Cell Content </div>
                </div>
              </div>
            </div>
          </div>

By default a cell div will span the entire 12 columns. You can adjust the number of columns the cell div spans by giving it additional classes of col-x-sm, col-x-md, and col-x-lg, where "x" is replaced by the number of columns you want the div to span. (See the "Responsive Grid" section below for further explaination on these classes.)

Responsive Grid

cell divs can be span a different amount of columns at different screen sizes [2]. The col-x-sm class will determine the amount of columns it will span on small screen sizes, col-x-md will determine columns spanned on medium screens, and col-x-lg determines how many columns it'll span at larger screens. If you want the cell to span the same number of columns at all sizes, you only have to use the correct col-x-sm, you do not have to set the col-x-md amd col-x-lg as well. Similiarly, if the cell spans the same number of columns on both medium and large screens, you only need to use a col-x-md class.

Grid Gaps

By default, the grid-container divs do not have any grid gaps between columns. You can add gaps by an additional class of either grid-gap-10, grid-gap-30 or grid-gap-30 to the grid-container div, depending on how much of a grid gap you want.

There is some built in repsoniveness to the grid gap classes. While the grid-row-gap will remain at the set number (50px for grid-gap-50 and 30px for grid-gap-30) at all sizes, the grid-column-gap will automatically decrease at certain screen widths[2]. On medium screens grid-column-gap will not go beyond 30px, and on small screen sizes it will not go beyond 10px. This is to ensure that the page content is properly responsive and text wraps appropriately.

Mobile Account Links

The first content in the navigation is the account-mobile section, which contains the "Log in"/"Log out" and "Create Account" links. These only appear in the mobile dropdown menu on small screens, and the rules for which buttons appear based on if the user is logged in or not is the same as the "account" section in the header. See header documentation for more details.

Navigation Items + Submenus

The rest of the lis contain the links for the different top level pages. The li for pages with submenus should have the class has-submenu and the parent a tag should have the attributes aria-haspopup="true" and aria-expanded="false". The links to the subpages are then listed in the nested ul in the parent li. Only the first level of child pages are included in the global navigation. If a child page has its own child, it is not included in the global navigation.

Current Navigation Item Styling

The a of the current page should recieve the class current. If the page in question is the parent of a dropdown, the current class should also be added to the li with the has-submenu class for that page. If the current page is a subpage in a dropdown, both the page itself as well as the parent dropdown should have the current class applied.

Buttons

All buttons should be given the class button. Additional styling can be given by adding the following classes:

  • primary - A "primary blue" button, used for most buttons on the site
  • secondary - A "slate" button, usually used when there are multiple buttons on a page and you want some to stand out less than the "primary" buttons
  • accent - a yellow button, used to stand out more than the standard primary buttons
  • hollow - used to stand out less than another button. Usually when buttons are right next to each other.
  • tertiary - A white button, used on dark backgrounds
  • hollow-white - a hollow button, but for use on dark backgrounds

All buttons, regardless of the additional styles applied to them, appear the same way when disabled.

Buttons that look like links

Giving a button the class link-match will make it stylistically look like a link. This should be used in places where its semantically correct to use a button but visually a button would be overwhelming (ex: the "+# more" button on the search result filter facets)

Round Buttons / More info buttons

The round class can be added to make a circle button. This will be used for triggering "More information" modals. Only one character - a "?" - should be visible in the button itself. The rest of the buttton label should be wrapped in a span with the class hidden so it is not visable to sighted user but is read by screen readers. 

        <button class="button primary round">
            <span class="hidden">Learn more about the X filter category</span>
            ?
        </button>

Button Groups

To add even spacing between buttons when multiple appear next to each other, wrap the buttons in a div with the class button-group.

        <div class="button-group">            
            <button class="button primary">Button 1</button>
            <button class="button hollow">Button </button>
        </div>

Optional and Required Inputs

When a form input is optional, put the text "(Optional)" in the label or legendwrapped in a span with the class form-note

The current plan is to have required be the default and mark optional inputs. However, if usability tests indicate that it's preferable to mark the required inputs instead, a class has already been prepared. Simply give the the label the class required.

Form Error Summary

When there are multiple inputs on a page that could potentially trigger an error message, an error summary should appear at the top of the page that list all the error messages on page and links to the input for each error message. Accordion

Accordions rely on jquery to work, plus some adapted custom Javascipt - see below.

To create an accordion component, give a div class of accordion. Each accordion "panel" should be within this div and is made up of two parts - the header and the content.

The header is created by giving a heading (an h3 is used in the example) the class of header. Within that heading there should be a span that contains the actual text of the header with the following attributes:

<span title="Click to toggle More Info section" class="toggle" role="button" aria-controls="section1" tabindex="0" aria-expanded="false">Heading Text</span>

The "aria-control" attribute should match the id on the corresponding content div.

The content section is created by giving a dive the class content. The id needs to match the "aria-control" of the header and the div should have the inline style of style="display:none;" by default so that it doesn't appear until the accordion is opened.

Small Accorions

To make a small version of an accordion for areas where screen real estate is tight (inside the NIGP Code Modal or in the Advanced Search interface), give the div with the class accordion the additional class of small-accordion.

            <script type="text/javascript" id="slideToggleScript">
              $(document).ready(function(){
                $(".toggle").click(function(){
                  toggleContent(this);
                });

                $(".toggle").keydown(function(event){
                  var key = event.which || event.keyCode;
                  if(key == 13) {
                    $(this).click();
                    event.preventDefault();
                  }
                });

                $("input.js-modal").click(function(){
                  $("#js-modal .toggle").click(function(){
                    toggleContent(this);
                  });

                  $("#js-modal .toggle").keydown(function(event){
                    var key = event.which || event.keyCode;
                    if(key == 13) {
                      $(this).click();
                      event.preventDefault();
                    }
                  });
                });
              });


              function toggleContent(buttonClicked) {
                //getting the next element
                var contentID = "#" + $(buttonClicked).attr('aria-controls');
                //checking if its already visible
                if ($(buttonClicked).attr('aria-expanded') === 'true') {
                  $(buttonClicked).attr("aria-expanded", "false");
                }
                else {
                  $(buttonClicked).attr("aria-expanded", "true");
                }
                $(contentID).slideToggle(0);
                return false;
              };
            </script>

No Javascript Fallback CSS

There are a number of components featured on the site that rely on javascript being enabled in order to function properly. In cases where a user has javascript disabled in their browser, there are some fallbacks put in place. While using javacript is highly encouraged as it will ensure the mose pleasant and user friendly experience and there are portions of the site that will just not be usable at all without javascript, these fallbacks will make sure that the inforamtional portoions site is still met the bare minimum for functionality.

To initalize the fallbacks, each page should have a call to the "nojs.css" file after the call to the pb-public.css file that is placed within a noscript tag as such:

<noscript> <link rel="stylesheet" href="css/nojs.css"></noscript>

If the nojs.css is called, the following things will happen:

  • All accordions panels will appear as opened
  • The reveal modal div will be displayed inline within the page based where it was placed in the HTML
  • On small screens the navigation toggle will be open by default and cannot be closed
  • The sideback subnavigation will not disappear on small screens

NIGP Codes Accordion

Accordions that are used to display lists of NIGP codes have unique styling, where that list of NIGP Codes is displayed in an unordered list or a table. To apply this styling, add the class nigp-accordion to the same div that has the accordion class.

Static Accordion

For static displays of NIGP codes, use a ul within the content div and it will style properly without any additional adjustments.

To mark inactive codes where the entire class is inactie, you can add the class inactive to the span with the class toggle in the header and then the inactive to the ul in the content div. This will add the "inactive" note to both the header of the accordion as well as every list item within the accordion.

If only one item is inactive within a otherwise active class, you can just put the class inactive on the individual li of the inactive item.

Interactive Accordion

Interactive NIGP code accordions are used in the NIGP Code Modal for managing which NIGP codes have been selected, either for email notification sign up or for adding to advanced search criteria. In this case a "remove" button has to be present for each item as well as each class. To display this, use a table with three columns: one for the code, one for the description, and one for the "remove" button. Give the tr for the table header the class hidden so it isn't visually displayed but is still read by screenreaders.

Buttons with the class button that are placed outside the table but inside the accordion content div are used removing all the items in a class. These are full width by default. A button for removing all classes placed outside the accordions will need to be given the class fw-input to match this styling.

If a single item in a class is inactive, you can put the class inactive on the individual td that contains the description for that item. If the entire class is inactive, you can put the inactive on the table and it will automatically give the second td in all trs the inactive styling.
